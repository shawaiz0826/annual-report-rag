# Decision log

One row per decision: what was chosen, why, what was considered, and when to revisit.

| # | Decision | Why | Alternatives considered | Revisit when |
|---|---|---|---|---|
| 1 | **Hand-written pipeline, no LangChain / LlamaIndex** | Every line must be explainable in the interview; frameworks hide retrieval, prompting and error handling behind abstractions that are hard to debug and tune. | LangChain LCEL, LlamaIndex query engines. | Never for this size; a framework earns its place only when many providers/loaders must be swapped by non-authors. |
| 2 | **Protocols with one implementation each** (`EmbeddingModel`, `VectorStore`, `LexicalIndex`, `LLMProvider`, `SessionStore`, `DocumentLoader`, `ChunkingStrategy`) | The seams are the scaling story: swap Chroma→Qdrant/pgvector, SQLite→Redis, BM25→OpenSearch without touching callers. Building a second implementation now would be speculative. | Abstract base classes; building Qdrant now. | When a production deployment needs multi-node search or multi-user sessions. |
| 3 | **Nothing about the dataset in code** — discovered at ingest or declared in config | Adding an issuer/year/sector must be "drop files, re-run ingest". Hard-coding "BMW 2023 = Finance N.V." would be brittle and would hide the real problem (entity ≠ issuer). | A hand-written manifest of documents. | Never; a manifest can be *generated* from the catalog if a reviewer wants to pin profiles. |
| 4 | **LLM document profiler with code-level validation** | Only a reader can tell a subsidiary's report from the group's; code cross-checks the parts it can (unit declarations found in the text, fiscal year and currency present, group/subsidiary flag consistency) and lowers confidence instead of failing. | Regex-only profiling; trusting file names. | If profiling cost matters at 1000× documents: cache by content hash (already) and use a cheaper model for profiling only. |
| 5 | **Facts layer (extract → reconcile → SQLite) in addition to RAG** | Numeric questions deserve verified, cited numbers with unit and currency, not whatever chunk ranks first. Extraction happens once at ingest, so answering is cheap and deterministic; reconciliation across reports gives confidence and restatement notes for free. | Pure RAG with the model reading pages at query time. | If documents change daily: run extraction as a background job keyed on content hash (the raw-facts-per-document layout already supports incremental re-reconciliation). |
| 6 | **Arithmetic in Python (`compute_metric` with `simpleeval`)** | LLMs make arithmetic errors; growth, margins and differences must be reproducible and carry fact-id provenance. `simpleeval` evaluates registry formulas without `eval`. | Let the model compute; a hand-coded function per metric. | Add new formulas to `registry.yaml`, not code. |
| 7 | **Hybrid retrieval: BGE-small dense + BM25, fused with RRF** | Dense catches paraphrase ("profit" ↔ "net income"); BM25 catches exact numbers, years and labels. RRF needs no score calibration. Fiscal year is a query term, never a hard filter, because prior-year figures live in later reports. | Dense only; a cross-encoder reranker. | Add a reranker (listed in the roadmap) if eval shows the right page in top-30 but not top-8. |
| 8 | **Page expansion for numeric chunks** | Statement pages are tables; an 800-char window cuts rows from headers. Attaching the whole cleaned page for table/numeric hits gives the model the column headers it needs. | Larger chunks everywhere (hurts precision on narrative). | If pages exceed the context budget: expand to the enclosing table only. |
| 9 | **Fixed-window chunking, page-bounded, with a provenance header** | Simple, predictable, and the header (`[entity | type FY | currency unit | p.N]`) is embedded on purpose so dense retrieval respects entity and year. | Section-aware chunking (roadmap). | When documents have reliable section structure (XBRL/HTML filings). |
| 10 | **Duplicate text-run removal in the PDF loader** | The Ford FY2023 file draws each page 2–3×; this can only be fixed before layout analysis. The rule is generic (token coverage ≥ 80 % of earlier runs) and verified to drop nothing in healthy files. | Positional de-duplication with a wide tolerance (merges `ll` in small fonts); OCR. | If a file with genuinely repeated passages appears, lower the threshold per file via config. |
| 11 | **Tool-calling agent with a mandatory `final_answer` tool** | Forces structured output (citations, caveats, confidence, entities/years/metrics used) on every turn; code enriches and verifies citations against the tool results of the run, dropping anything the model invented. | Free-text answers parsed with regex; a JSON "plan" protocol. | The JSON plan fallback is specified in the execution plan for models without tool calling; the chosen models passed the smoke test, so it was not built. |
| 12 | **Model knowledge off by default, visibly labelled when on** | Grounding is the product. A `--show-model-knowledge` flag shows the difference in the demo. | Always allow prior knowledge. | Never for a financial analyst tool. |
| 13 | **Slot memory + condensed history for follow-ups** | "And 2022?" needs the last entities/years/metrics; a four-turn window keeps prompts small. | Full history; summarisation by an LLM call. | Multi-user scale: move sessions to Redis (interface exists). |
| 14 | **Single trace schema feeding `/why`, cost reporting and evals** | One source of truth for debugging and measurement; evals read the same traces users see. | Separate logging and eval instrumentation. | — |
| 15 | **No recorded answers; automatic model fallback instead** | Every answer is produced live by retrieval → facts → model. A replay cache of rehearsed answers was built first and removed at the owner's request (2026-10-11): it made the demo look safer while hiding exactly the failure modes an interviewer would ask about. Resilience now lives in the client — a failed call (daily quota, upstream 429/5xx, missing endpoint) is retried on `LLM_MODEL_FALLBACK`, and the answer, footer and trace say which model replied and why. Evals disable the fallback so a per-model report is answered by that model. | Replay cache (removed); mocked provider for demos. | If a paid model becomes the primary, point the fallback at a second paid model. |
| 16 | **OpenRouter with free models** (`nvidia/nemotron-3-ultra-550b-a55b:free` primary) | Owner's choice: zero cost; the client is OpenAI-compatible so `/model anthropic/claude-sonnet-5` works unchanged once credits exist. Reasoning tokens are excluded from content and the token budget is sized for them. | Paid Sonnet/Gemini (configured, not used). | If free endpoints are rate-limited during a demo: add credits or switch `LLM_MODEL`; the fallback model catches single-call failures. |
| 17 | **Terminal CLI is the primary demo; API + Streamlit + Docker included** | The brief allows either; the CLI shows `/why` and `/facts` best. The service layer makes the web app a thin wrapper, so including it costs little. | Web-only. | — |
| 18 | **SQLite (stdlib) for facts and sessions** | Zero dependencies, transactional, inspectable with any tool. | DuckDB, Postgres. | Postgres when multi-user. |
| 19 | **Confidence rules in reconciliation** (0.8 original / 0.6 comparative / 0.95 agreeing / 0.6 + note on disagreement) | Simple, explainable, and they surface in answers. | A learned confidence. | — |
| 20 | **EBITDA in the registry although the 10-Ks do not report it** | The brief names EBITDA explicitly; the tool answers "not in the provided documents" with coverage instead of guessing. | Omit. | — |
